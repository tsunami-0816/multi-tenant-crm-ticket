## P0 致命问题（必须修）

### P0-1：本地消息表定时任务扫描，导致 Kafka 端到端延迟不满足 M7

**问题描述**：
架构 §3 链路 3 写"定时任务扫 local_message，send Kafka"。但基线 M7 要求"工单状态变更 → 客户时间线可见，端到端 P99 ≤ 2s"。如果定时任务 fixedDelay = 5s，消息投递延迟就是 0~5s，P99 ≤ 2s 直接不达标。

**影响范围**：M7 指标必挂；真实项目里这也是常见错误——本地消息表模式不是必须用定时任务。

**修改建议**：
改成"**事务提交后立即发送 + 失败才落本地消息表重试**"：
- 业务方法加 `@Transactional`
- 事务提交后通过 `TransactionSynchronizationManager.registerSynchronization()` 的 `afterCommit()` 回调，立即发 Kafka
- 发送成功 → 不写 local_message
- 发送失败 → 写 local_message 兜底，定时任务 5s 扫一次补发（只处理失败的）
- 这样正常路径延迟 = 业务事务时间 + Kafka 生产延迟，P99 ≤ 2s 可达成；失败兜底才走定时任务

## P1 重要问题（应当修）

### P1-1：MyBatis-Plus 多租户插件对 XML 手写 SQL 不生效

**问题描述**：
MyBatis-Plus 多租户插件自动拼接 tenant_id 条件，但只对 MP 自动生成的 CRUD 和注解 SQL 生效。XML 里手写的 `SELECT * FROM customer_follow WHERE customer_id = ?` 不会自动加 tenant_id，存在数据越权风险，M3 指标挂。

**修改建议**：
- 在开发规范（step04）里写死：禁止 XML 写不带 tenant_id 的业务查询；确需手写 SQL 时，XML 里必须显式写 `#{tenantId}` 条件
- L3 集成测试强制覆盖"手写 SQL 查询也走租户隔离"场景
- 架构文档 §4 数据模型补一条约束说明

### P1-2：Redis 缓存冷启动命中率达不到 M4（≥95%）

**问题描述**：
刚启动时 Redis 是空的，直接压测命中率会很低。M4 要求 ≥95%，需要预热机制。

**修改建议**：
- JMeter 压测前先跑一轮预热（循环访问热点客户详情 100 次），再正式压测
- README 和压测报告里注明"数据是预热后"
- 不做主动预热脚本（MVP 过度设计）

### P1-3：客户时间线 UNION 查询缺分页方案

**问题描述**：
§3 链路 4 用 UNION 合并跟进记录和工单事件，没写分页。客户时间线条目多了会慢，M5 性能指标挂。

**修改建议**：
- 改成"应用层分页"：分别查 follow 和 ticket 两类最近 N 条（各 limit 50），内存合并后按时间排序分页
- 不做数据库层 UNION 分页（复杂且慢）

### P1-4：接口清单缺登出/刷新 token/工单分配接口

**问题描述**：
§5.3 接口清单只有 12 个，但业务上客服要分配工单给具体人（`assignee_id` 字段在表里但没有对应接口）。登出和 token 刷新也是标配。

**修改建议**：
- 补 `POST /api/auth/logout`（JWT 黑名单，MVP 简单实现：Redis 存过期 token）
- 补 `PATCH /api/tickets/{id}/assign`（分配客服）
- 不做 refresh token（MVP 用 access token 2h 过期即可）

## P2 建议优化（不阻塞）

### P2-1：JWT 过期时间和密码加密强度未写明

- JWT access token 有效期写 2h
- BCrypt strength = 10

### P2-2：业务错误码表未列具体值

- 40001 未登录 / token 过期
- 40003 无权限（角色不匹配）
- 40401 客户不存在
- 40402 工单不存在
- 40901 工单状态机非法流转

### P2-3：docker-compose 健康检查命令未写

- MySQL: `mysqladmin ping`
- Redis: `redis-cli ping`
- Kafka: 用 kafka broker 脚本
- 服务: `curl http://localhost:port/actuator/health`
